# studsovet-sprees

Три игры студсовета плюс реестр участников и рейтинг. Фронт — React 18 + Vite +
Tailwind v4, сервер — NestJS с сокетами. Устройство и команды: [README.md](README.md),
слои компонентов и правила стиля: [src/components/README.md](src/components/README.md).

## Проверки перед тем, как сказать «готово»

```bash
npm run build     # tsc -b + vite build
npm test          # vitest
npm run lint      # eslint; ошибки в backend/ бывают унаследованные — сверяйся с `npx eslint src`
```

Деплой на test.traapp.ru — только по прямой просьбе: `npm run deploy:test:front`
(фронт), `npm run deploy:test` (всё с тестами).

## Обязательное правило: углы

**Ни один радиус в этом проекте не выбирается на глаз.** Это не стилистическое
пожелание, а инвариант: радиус контейнера равен его отступу плюс радиус того,
что стоит в его углах. Тогда ребёнок, вставленный на величину отступа, имеет с
контейнером общий центр дуги. Нарушение не выглядит поломкой на скриншоте — оно
выглядит «немного не так», и поэтому проходит незамеченным.

Правило целиком описано в [src/components/README.md](src/components/README.md)
(разделы «Rounding» и «Spacing») и охраняется [src/styles/concentric.test.ts](src/styles/concentric.test.ts).

Что это значит на практике:

1. **Радиус не пишется руками.** Никаких `rounded-md`, `borderRadius: "12px"`,
   `radius="var(--radius-2xl)"`. Разрешены только `rounded-pill`, `rounded-full`
   и шкала `rounded-control-*` — у контрола радиус равен половине его
   фиксированной высоты, и он для всего остального исходная точка.
2. **У `Card` угол задаётся через `content`,** а не через `radius`. `content`
   называет то, что стоит в углах: `"sm" | "md" | "lg"` для контрола такого
   размера либо `cardRadius(…)`, если в углу другая карточка.
3. **Карточка в углу карточки требует `content={cardRadius(отступ_внутренней)}`.**
   Умолчание `content="md"` здесь всегда неверно. Если вложенная карточка стоит
   в середине стопки и углов не касается, файл вносится в `NESTED_MID_STACK` в
   тесте — с комментарием, что именно держит углы.
4. **Голый DOM-элемент с фоном или рамкой обязан взять угол откуда-то:** класс
   `ui-surface` (CSS-сторона хука), выведенный `borderRadius` или круг. Квадратный
   угол внутри скруглённой карточки — ошибка, а не решение.
5. **Угол передаётся вниз хуком, а не копированием.** `useInnerRadius()` в TSX
   (`MediaImage`, `AudioPlayer`, `VideoPlayer`, `Inset`) и `--card-inner-radius`
   через класс `ui-surface` в разметке. Контракт закреплён в
   [src/components/atoms/Card/innerRadius.test.tsx](src/components/atoms/Card/innerRadius.test.tsx).
6. **Контрол, который не может нарисовать запрошенный угол, заворачивается в
   `Inset`,** а не раздувается до нужного размера.

Списки-исключения в тесте (`SELF_EVIDENT`, `FIXED_SHAPES`, `UNCONSTRAINED`,
`NESTED_MID_STACK`) пополнять можно — но каждая строка там это решение по
дизайну, которое видно в диффе и разбирается на ревью. Добавлять имя, чтобы
замолчать упавший тест, нельзя.

## Прочее

- Цвета, отступы, шрифты — только токены из `src/styles/tokens.css` (или
  `tokens.ts` для по-настоящему динамических значений). Хекса в компонентах нет.
- Отступы задаёт `gap` родителя; `margin` для разделения не используется нигде.
- Импорт через барели (`components/atoms`, `components/molecules`, …), а не
  вглубь папки компонента.
- Приложение открывается как мини-приложение Telegram: узкий экран и тач — не
  краевой случай, а основной. Вложенная горизонтальная прокрутка спорит с
  жестом закрытия мини-приложения.
